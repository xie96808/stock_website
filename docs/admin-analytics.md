# 后台「数据」页（用户数据可视化）

后台新增一个独立标签 **数据**（`admin/analytics.js` + `analytics.css`），只读，管理员专用；其它标签不变。

## 数据从哪来
| 指标 | 来源 | 历史可回溯 |
| --- | --- | --- |
| 注册 / 新增 / 禁用 / 注销 | `users` | 是 |
| 活跃（DAU/WAU/MAU）、留存、沉睡、开局率 | 当天有 **心跳 / 登录 / 开局** 之一 | 是（登录、开局一直有记录） |
| 各玩法局数、对战局数 | `game_sessions` / `pvp_matches` | 是 |
| 韭币流通、上榜意愿 | `users` | 是 |
| **在线人数、使用时长、Top 3、访问时段** | 客户端心跳 | **否，从本版本上线起累计** |

## 心跳
- 客户端 `js/heartbeat.js`：已登录 + 页面可见 + 最近 5 分钟有操作，每 30 秒 `POST /api/v1/me/heartbeat`。
- 服务端 `server/src/lib/activity.js`：
  - 两次心跳间隔 < 10 秒忽略；> 5 分钟视为新一次访问（间隔本身不计时）；单次最多计 75 秒。
  - 写三张表（迁移 `029_user_activity.sql`）：`user_presence`（最近心跳）、`user_activity_daily`（每人每天秒数 + 访问次数）、`user_activity_hourly`（每人每小时是否活跃，保留 100 天）。
  - 在线 = 最近 90 秒内有心跳。
- 管理员账号不上报、不计入任何统计；已注销账号不计入。游客（未登录）无法统计。
- 日期一律按北京时间（Asia/Shanghai）。

## 接口
`GET /api/v1/admin/analytics?days=7|14|30|90`（`days` 限制在 7–90，默认 30）。需要管理员登录，不需要二次验证（只读）。

## 部署
迁移在 API 启动时自动执行。**需要部署 API** 才有数据接口和心跳；静态站点单独更新只会多出一个会报错的「数据」标签和 404 的心跳请求（客户端静默忽略）。
