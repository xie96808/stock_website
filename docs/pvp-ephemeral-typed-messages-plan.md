# PvP 自由输入消息开发计划

> 状态：已在功能分支实现，等待评审与合并。
> 基线：当前 `main` 中的 PvP 预设台词与临时气泡实现。

## 1. 目标与边界

在现有对战房间的预设消息基础上，增加玩家自行输入短消息的能力。消息是短暂的对局表达，不做聊天记录页、不持久化、不进入结算或复盘；画面中只显示最近一条消息，下一条覆盖上一条，定时后自动消失。

沿用当前链路：`#pvpMsgOpen` 打开消息选择器，`POST /pvp/matches/:id/taunts` 发送，WebSocket `match.taunt` 广播，气泡放在各自头像旁。当前客户端气泡约 3.2 秒消失，服务端事件只保留在内存约 60 秒以供限流窗口清理；当前消息正文只允许固定台词。

## 2. 交互方案

### 2.1 输入框位置

- 保留买入／消息／保持三按钮布局，不在房间常驻一条聊天栏，避免挤占 K 线和行动区。
- 玩家点现有“消息”按钮时，打开现有 `#pvpMsgPicker`；在固定台词按钮下方增加一行输入区：单行输入框、字数计数、发送按钮。
- 选择器锚定在底部行动栏上方，不推动图表跳动；屏幕较矮时限制高度并让选项区滚动，输入行保持可见。
- 发送后收起选择器、清空输入框并把焦点留在“消息”按钮；若发送失败，保留草稿并显示短错误提示，避免文本丢失。

### 2.2 长度与输入行为

- 最多 **32 个 Unicode 码点**，前后空白裁掉；空字符串拒绝发送。
- 拒绝控制字符和换行，首版仅支持纯文本；不支持图片、链接预览或富文本。
- Enter 发送；IME 输入法正在组合文字时不发送，避免中文拼音上屏被 Enter 抢走。
- 发送按钮在空输入、正在发送、非 `playing` 状态下禁用。固定台词继续可用，按现有交互发送。

### 2.3 消息展示与消失

- 发送成功后，消息出现在发送者头像附近的现有气泡；对手收到同一 `match.taunt` 事件后，在对手头像旁显示。
- 保持“每方最多一条气泡”：同一玩家的新消息替换自己的上一条；双方可同时各显示一条。
- 自由输入气泡显示 **4.5 秒**后清除；沿用现有 3.2 秒的预设台词时长，避免更改旧消息节奏。计时从气泡实际显示开始，刷新该方新消息时重新计时。
- 气泡最多两行，正文换行显示而不以省略号隐藏主要内容；建议宽度上限 220px / 80vw，并在窄屏验证不遮住操作按钮、头像和计时。
- 使用 `textContent` 插入消息。关闭房间或切换对局时清除两边定时器、气泡文本及未发送草稿。

## 3. 服务端与实时消息

- 扩展现有 taunt 校验：保留六条固定台词，同时接收通过校验的自由文本；服务端重新 trim、检查字符数及控制字符，不能只依赖浏览器限制。
- 继续限定发送人必须是该局玩家、比赛状态必须为 `playing`；沿用 `requireUser`、Origin／CSRF 检查和现有每用户 API 限流。
- 保留现有每人至少间隔 2.5 秒的房间级限制，以及近 60 秒最多 20 条的内存限制；拒绝时返回现有错误包，不广播。
- 继续通过 `noteMatchTaunt` 只推送给同一房间两方；不增加数据库表、历史查询接口或客户端历史列表。60 秒内存窗口仅用于限流/过期清理，不是消息存档。
- API 日志不得记录消息正文。服务进程重启后内存消息自然清空；对局结束后拒绝继续发送。

## 5. 实施顺序

1. 增加服务端自由文本校验和边界测试，确保协议仍只接受 `{text}`。
2. 在原消息选择器内增加输入行和移动端布局，不改变交易按钮的位置。
3. 复用当前 taunt REST + WebSocket 通路发送自定义文本；加入前端限长、计数及 IME 保护。
4. 将自定义消息气泡时长设为 4.5 秒；保留预设消息 3.2 秒；补充同方消息覆盖与房间销毁清理。
5. 执行 PvP 单元/界面测试及现有主回归；使用双浏览器会话验收发送者、对手、连续消息、窄屏和断线后重进状态。

## 6. 验收标准

- 消息按钮展开后，预设台词仍在，输入行紧接预设列表且不会遮挡交易按钮。
- 双方都能看到自定义消息；发送者和接收者都在规定时长后自动清空；新消息替换旧消息，不形成可翻阅记录。
- 32 码点上限在浏览器和服务端均有效；空消息、控制字符、超长消息、局外用户、已结束对局均不广播。
- 中文输入法组合态按 Enter 不会误发；发送失败时草稿保留，成功后清空。
- 预设台词原有行为和 3.2 秒显示时长不变；自由消息不会改动对局 revision、计时、动作或结算。
- 320px 宽度、375px 宽度和桌面尺寸均无横向溢出；减少动态效果偏好下，气泡仍可读且按时消失。

## 7. 产品取舍

推荐短文本、单气泡、自动消失；暂不做可回看聊天记录。4.5 秒只影响自定义消息，较现有预设消息多 1.3 秒，用于阅读 32 字上限的两行内容。若用户实测认为气泡停留过久或太短，可先调整客户端常量，不涉及迁移或数据兼容。
